# Hosted-MCP catalogue sweep, 2026-10-13

*This is evidence for the next catalogue rulings. It sits next to `hosted-mcp-connection-scope.md`, the plan, and `integration-readiness-matrix.md`, the live state. No vendor account or consent was used. Every verdict comes from public metadata and vendor documentation. Every first-pass "fit" or "conditional" was re-measured by an independent refuting pass; first-pass "no" and "unreachable" verdicts were not.*

## Method

- **Population.** 61 apps were measured on 2026-10-13 (PostHog, Intercom and Salesforce were measured twice and are merged into one row each). The three vendors from the 2026-10-09 order (Canva, Miro, ClickUp) are a separate population: their "fit" came from that earlier order, and they went through the same refuting pass on 2026-10-14. The table has 64 rows.
- **Measured.** For each app the sweep looked for an official hosted MCP server. Community and third-party servers don't count. It then measured three things without an account:
  1. an unauthenticated MCP `initialize`, recording the 401 and its `WWW-Authenticate` header;
  2. the protected-resource metadata;
  3. the authorization-server metadata: registration endpoint (DCR), CIMD support, revocation, scopes and grant types.
- **The bar** (plan §3, Wren): the credential can't write, meaning a read-only scope separate from write whose token reaches nothing that writes, and registration is self-serve through DCR or CIMD. Wren's 2026-10-14 ruling sharpens the first half: a read may leave only the vendor's record of that read (query history, results, usage counts); new content, notifications and third-party code are writes.
- **Refuting pass.** Every first-pass "fit" or "conditional" (31 apps, counting the 10-09 three) went to a second agent that hadn't seen the first pass's reasoning. Its job was to refute the classification: re-measure from scratch, read the vendor docs, and look for gates such as allowlists, review, plan limits and admin enablement. The final verdict is the refuting pass's wherever one ran.
- **How to read the columns.** *Read-only scope* and *Refresh* name their provenance: **advertised** means the discovery metadata says so, **documented** means a vendor page says so, **measured** means the refuting pass exercised it, and **unmeasured** means nobody did. An unauthenticated sweep cannot show what a token actually does; see *Not measured*.
- **Sources.** Each row cites one to three public pages, every one copied from the measurements rather than added afterwards. "metadata probe only" means the decisive claim rests on the unauthenticated discovery documents. All 115 links were fetched on 2026-10-14: 109 answered 200, and six help-center pages (Coda, Egnyte, Evernote, Otter, Salesforce, Superhuman) refuse scripted fetches with 403.

## Headline

- **Seven fits survived the refuting pass:** Basecamp, Buildkite (`/mcp/readonly`), Close, Grafana, Honeycomb, Hugging Face and Otter.ai. Honeycomb ships only if an authenticated capture shows `run_query` leaves nothing but query records (Wren, 2026-10-14). Basecamp, Grafana, Honeycomb and Hugging Face support CIMD and need no stored registration. Buildkite, Close and Otter need DCR client storage.
- **Within the 10-13 sweep, 6 of 13 first-pass fits were overturned:** Cloudflare, Jam, PostHog and Trello to conditional, and Neon and Typeform to no. The three 10-09 fits (Canva, Miro, ClickUp) all dropped to conditional on the same re-check, so **9 of 16 first-pass fits fell overall**. Of the 15 first-pass conditionals, Cal.com, Lucid, Readwise and Slack fell to no and Zendesk to unreachable. See AX audit entry 80.
- **Most popular apps don't clear the bar.** They offer no read-only scope a client can request, whether through one catch-all scope, no scopes at all, or a read/write split the vendor always requests together (Notion, Stripe, Intercom, Asana, HubSpot, Salesforce, Klaviyo, Webflow, Wix, Mixpanel, Plane). Or they admit only allowlisted or reviewed clients (Figma, Vercel, Square, Dropbox, Egnyte, and Canva's hosted endpoint).
- **Final tally:** 7 fit, 17 conditional, 38 no, 2 unreachable.

## Why apps fell on the refuting pass

A read scope in metadata is not a credential that can't write. These are the reasons the refuting pass found, each in its row below:
- **The token behind the scope can still write:** Neon's read scope only filters the MCP's tool list; the bearer is the upstream Neon token, requested with create, update and delete scopes.
- **The read scope reaches things that write:** PostHog's `project:read` reaches a gateway calling connected third-party tools that can change data. Jam has irreversible delete tools and no doc mapping tools to scopes.
- **The requested scope doesn't bound the grant:** Typeform requires every scope to connect; Cloudflare's requested scopes only preselect a consent page where the user can choose Full access; Cal.com's hosted server ignores the requested scope and asks for a fixed set that includes writes.
- **"DCR" isn't self-serve:** Zendesk's undocumented registration endpoint returns one hard-coded shared client id to every caller.
- **Read-only is a separate resource, not a scope:** Lucid.
- **The MCP gates on a catch-all scope:** Readwise's MCP accepts only tokens carrying `openid`.
- **Gates absent from metadata:** Canva's waitlist and review for `mcp.canva.com`; ClickUp's redirect-URI allowlist with review, documented through 2026-07-27 and gone from the 2026-10-07 rewrite; Trello's default client-domain allowlist; Slack's Marketplace listing requirement; Miro's optional Enterprise admin allowlist.

## What each surviving fit still needs

These come from the refuting pass and are unmeasured until each app's authenticated capture.
- **Basecamp:** whether a token granted `mcp read` is refused on writes (the 401 challenge defaults to `mcp full`), and whether refresh needs `offline_access`.
- **Buildkite:** never pin tools that need `read_secrets_details` or `read_job_env`. There is no revocation endpoint, so a token lives out its lifetime after disconnect.
- **Close:** only the DCR path can yield `mcp.read` (pre-registered Close apps always get full access); the granted scope must be checked after consent. No free plan, so testing needs a trial org.
- **Grafana:** Grafana Cloud only. The free plan allows 3 active AI users a month, and each connected MCP user counts. Revocation is UI-only.
- **Honeycomb:** the `run_query` capture above. A Team Owner must enable Honeycomb Intelligence first; the EU region is a separate authorization server and would be a second entry.
- **Hugging Face:** the server doesn't filter write tools by scope, so whether the Hub refuses a `read-mcp` token on writes is the capture's question. Space tools forward the user's token to third-party Gradio Spaces, which the 10-14 ruling counts as a write, so they must never be pinned.
- **Otter.ai:** the protected-resource metadata lists the authorization server with a trailing slash that its issuer lacks, so the entry must hardcode the issuer. Whether DCR accepts our redirect is unmeasured.

## Runtime adapters (same day)

The next adapter after OpenCode was measured by the operator from the installed binaries in a scratch directory on 2026-10-13: `--help`, plus Qwen and Gemini runs against a loopback stub. No logins and no model turns. This section is operator-reported and was not independently re-run. Qwen Code has since been measured end to end on a clean box for #2142 (TASK-198), which supersedes the Qwen line below.

- **Qwen Code 0.25.1** (fit rank 1): headless `-o stream-json` (JSONL in the Claude-Agent-SDK shape), per-spawn `--mcp-config`, `--bare`, and an OpenAI-compatible provider that can point at our provider proxy. Public seats need HOME isolation, because it reads `~/.qwen/.env` and `~/.env`. Its built-in subagents can run on the operator's other credentials, so they must be excluded.
- **Gemini CLI 0.64.0:** headless `-p … -o stream-json`. Folder trust is on by default and pulls in workspace config. There's no per-run MCP flag, only `settings.json`.
- **GitHub Copilot CLI 1.0.97:** headless `-p --output-format json` and `--additional-mcp-config`. It's proprietary, and whether its terms allow serving public third-party seats is unmeasured. Telemetry is on by default.
- **Goose 1.54.0:** `goose run --output-format stream-json`, with per-spawn extensions as flags. The default mode auto-approves every tool, and the developer builtin (shell plus edit) is enabled.
- **Crush 0.98.1:** `run` has no JSON output, and a project `crushrc` or `crush.json` `$(…)` executes at load. Unsafe for public seats.
- **Cursor CLI** and **Amp:** prompts and threads go to the vendor's servers on the supported path.

## Not measured

- Any authenticated behaviour: whether a read-only token reaches `tools/list`, actual granted scopes, `expires_in`, and revoke effectiveness. Those come from a capture taken with an owner's consent, one per app, before an entry ships.
- Whether a DCR registration accepts a non-loopback `https://api.commonly.me/...` redirect at each vendor. Testing that would create a client, so it wasn't done.
- First-pass "no" and "unreachable" verdicts had no refuting pass, so a gate that would have rescued one of them could have been missed.
