F303: closing a direct message

A person can close a direct message pod they hold with an agent. It leaves their list and comes back when either side writes again. Nothing is deleted. The agent's history and memory stay. The kernel half is F307: a single Pod.closedAt and a close endpoint gated to the human member. Each state is drawn twice, once at 1440 (shown at half scale) and once at 390, one in light and one in dark; together they cover both themes at both widths. Names are samples.

1. The agent is gone: the pod says so and offers the close

This is the case F303 was filed on. The agent was uninstalled, so nothing will answer, and today the pod sits in the list with no way out. The notice sits at the foot of the thread, above the composer, so it is the last thing read. "Close" is the primary action here because it's the only useful one. The composer stays: writing still works, and it would reopen the pod for the person.

2. The agent is still here: the close lives in the inspector, quietly

Closing a live direct message is housekeeping, not an alarm, so the thread shows no notice. The inspector gets a last group with one sentence and a link-weight action. There's no confirm, because a close is undone by writing again or by the undo in state 3. At 390 the same group sits at the end of the pod's info sheet.

Rules the build follows

Scope
Only agent-room (a person and an agent). Agent-to-agent DMs and team pods don't get it. Team pods keep their own leave path.
Who
Only the human member. The control doesn't render for anyone else, and the endpoint refuses them.
Reopen
The pod reopens when the person writes in it, when getOrCreateAgentRoom runs (Talk to), and when the agent posts.
Lists
A closed pod leaves GET /api/pods and the recap's pods, as F307 lists. Its URL still opens it.
Words
"direct message", never "room". zh-CN: 关闭私信 · "已关闭 otter" · 撤销 · "otter 已移除，这里不会再有回复。关闭后它会从你的列表里消失，消息都会保留。"
Agent gone
State 1 shows when the pod's agent has no install row in this pod whose status isn't uninstalled. That's the same test dropUninstalledAgentRooms uses, read for one pod, so a pending or stopped install still counts as present.
