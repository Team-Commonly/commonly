D115: agent health

One page that answers, for the agents in your own pods, which did useful work, which woke and said nothing, failed or never picked up, what the hosted ones cost, and which need you. It sits under Your team at /v2/agents/health, a second option beside Agents in the page head. It reads only counts and fixed codes from GET /api/agents/health (design note: docs/architecture/fleet-health.md), so no message text appears anywhere on it. Each state is drawn at 1440 (the main column, rail and sidebar left out) and at 390, one in light and the other in dark. Names, pods and numbers are samples.

1. A busy day: one row per agent install, the split and what needs you

The outcome bar covers wakes that asked for something (mentions, chat, decisions, joins and other types). Heartbeats get a column of their own, so an agent that rightly stays quiet on a heartbeat doesn't drag its share down (the design note's open question, answered as proposed). A row that needs a person names the cause in a word or two. The sentence that says what to do already exists on the agent's own page (the agent page's spawn-failure copy), and a row click opens it, so this page writes no new fix text. A wake still in flight is striped and never counted as failed. Cost is shown for hosted agents only; an agent on someone's own computer runs on their account, and the page says so instead of showing zero.

Rules the build follows

Whose agents
The installs in the viewer's own pods: Pod.find({ members: viewerId }), then the AgentInstallation rows in those pods, filtered before any count. No admin view and no admin bypass, for a global admin too. An agent-dm pod appears only when the viewer is a member of it. An instance-wide view is D116's call, not this page's.
No message text
The response is an allowlist of counts, enums and times. It never carries payload, reason, errorMessage, details, error, args or result, and a test asserts that. The page draws only what the response holds, so nothing here can quote a message.
Asked
Every wake that isn't a heartbeat and isn't a digest. Posted = delivery.outcome posted. Declined = no_action or skipped (and a native run's emptyCompletion). Failed = outcome error or status failed. Never picked up = expired. In flight = pending, folding, or delivered with no outcome, and native runs queued or running; never counted as failed.
Heartbeats
Their own column: the count and how many posted. A quiet heartbeat isn't a decline.
Wakes by kind
The note's mapping: mentions, heartbeats, chat, decisions, joins. An unmapped type is listed by its raw name in code type (task.assigned), so a new type shows rather than vanishing. Digests are a count of their own.
Needs you
Only fixed codes, never free text. On someone's computer, from lastSpawnFailure: claude-signed-out, login, out-of-allowance, wont-start and codex-version mark the row Needs you, labelled Signed out, Login, Out of allowance, Won't start, Update Codex. tools-unavailable and model-unavailable count as Failed in the bar. Hosted, from errorKind: only config is Needs you; the rest count as Failed. The fix sentence stays where it already lives, agentManage.controls.spawnFailure.<code> on the agent's page. This split is a proposal; the build PR's review can move a code.
Offline
From lastSeenAt, past the runner's poll interval, shown as "Offline since" a time (today) or a date. Hosted agents show Running, or Paused from the install status, never a last-seen time.
Cost
Hosted: tokens and sandbox time from AgentRun, rounded (41k, 2 min). On someone's computer: "On your account". Never a zero, never a price.
Window
24 hours by default; 3 days and 7 days as long as event retention (AGENT_EVENT_DELIVERED_RETENTION_HOURS) covers them. An option retention doesn't cover isn't offered.
Row click
Opens the agent's own page, /v2/agents/:name/:instance, where its activity and the fixes already live. No trace viewer here.
Head
The page keeps Your team's head: title, and the Bring your own and Hire an agent actions. The Agents · Health switch sits beside the title and the window select joins the actions.
Scope line
"Agents in your pods", the install count, and "N need you" only when a row carries Needs you. Offline rows aren't counted in it: offline has its own badge.
Order
Needs you first, then offline, then by asked wakes, most first.
Words
"pod", never "room". "Runs on your computer", the label Your team's cards already use (yourTeam.card.where.local). zh-CN (proposed; the build runs the glossary two-pass): 健康状况 · 已回复 · 未回复 · 失败 · 未接收 · 进行中 · 心跳 · 需要你处理 · 由你的账户付费 · "最近 24 小时没有唤醒".
