# Commonly v4

Commonly v4 is a multiplayer harness for the agents people already use. It is a pod where humans and
their Claude Code or Codex agents share tasks, ask for decisions and leave receipts.
- Backend: Cloudflare Workers, with one Durable Object per pod.
- Local agents: a headless Go daemon runs them over ACP.
- Pod tools: agents reach them through one remote MCP server.
- Client: the main check is an API-level e2e. The web client waits on docs/design/client-options.md.

## Start every session here
1. `./init.sh`: installs dependencies, runs the baseline and prints which features pass.
   If the baseline is red, fix that before anything else.
2. Read `progress.md` (newest entry first) and `git log --oneline -15`.
3. Pick the first feature in `feature_list.json` with `passes: false` and no `blockedBy`. Work on that one
   feature only.

## The loop, one feature at a time
- **Red first.** Write the feature's e2e test from its `steps` and watch it fail for the right reason.
  Then build inward with unit tests for logic (red, green, refactor).
- **Verify at the API.** The feature's `test` command passes locally. A unit test alone never marks a
  feature passing.
- **Mark it.** Set `passes: true`. That is the only edit allowed to `feature_list.json`. Never delete,
  reword or reorder a feature to make it pass. If one is wrong, add a new feature and say why in
  `progress.md`.
- **Commit small.** One PR per feature, base `v4`, using `.github/pull_request_template.md`.
- **Log it.** Add a `progress.md` entry: what changed, what's next, and anything surprising.
- **Compact.** Compact or clear context at feature boundaries, never mid-feature. `progress.md` is the
  hand-off.

## Repo map
- `schema/`: JSON Schema, the only source of wire shapes. `schema/fixtures/` holds the examples that
  every test loads.
- `gen/ts/` and `daemon/internal/protocol/gen.go`: generated by `make gen`. Never edit them by hand.
- `worker/`: the Worker, PodDO, MCP server and auth. `daemon/`: the Go daemon and ACP.
- `e2e/`: the slice tests (Go). `scripts/`: generators and checks. `docs/`: design and lessons.

## Commands
- `make gen`: regenerate contracts after editing `schema/`. Commit both.
- `make preflight`: `check-gen`, `test` and `entropy` (budgets in `entropy.json`). CI runs the same.
- `make e2e`: boots the Worker locally and runs `go test ./e2e`.
- On the fleet Mac, Go and Bun come from `~/.commonly/toolchains/v4/bin` (the Makefile adds it).
  Never install anything globally.

## Rules
- **The schema is the contract.** No `oneOf`/`anyOf`/`allOf`. A union is a `type` enum plus
  `x-variants`. Cross-field rules are `x-rules`, enforced and tested in `worker/`.
- **Tokens.** An agent holds only a `cmr_` run token. It never sees `cmc_`, `cmu_` or a third-party
  credential. The server stamps receipts and the actor; it never trusts them from input.
- **Push wakes only.** Nothing polls. A change that only touches unaddressed agents wakes nobody.
- **Merging.** Green in the merge queue merges. Protected paths also need a fresh-context review and
  an Opus `GATE: PASS` at the PR head: `schema/`, `worker/src/auth`, `worker/src/mcp`,
  `daemon/internal/{acp,run}`, `install.sh` and `.github/workflows`.
- **Stay small.** Files at most 400 lines, functions at most 60, LOC caps per area. A new dependency or
  module gets a note in `docs/adr/`. Each report states lines added/removed and what it deleted.
- **Lessons.** A lesson lands in the same PR, as a test, a lint rule or a `docs/` note. Never only in
  private memory.
- **Stage skills.** Plan with Pocock `tdd`, review with Pocock `code-review`, and retro with pstack
  `reflect` at the end of a lane. Details: `docs/development/workflow.md`;
  docs map: `docs/INDEX.md`.
