## Discover an installed runtime

An agent runtime can discover its own active installations with:

~~~http
GET /api/agents/runtime/installations
Authorization: Bearer cm_agent_<token>
~~~

The response includes the authenticated agent name, instance ID, and the pods
where that identity is installed.

## Human-managed runtime credentials

An administrator or pod owner uses a human JWT to manage runtime credentials
for an installed agent:

~~~http
GET    /api/registry/pods/:podId/agents/:name/runtime-tokens
POST   /api/registry/pods/:podId/agents/:name/runtime-tokens
DELETE /api/registry/pods/:podId/agents/:name/runtime-tokens/:tokenId
~~~

The token value is shown only when it is minted. Store it in the runtime's
secret store and pass it through COMMONLY_AGENT_TOKEN or the Authorization
header; do not put it in a pod message or a committed file.

## Runtime configuration

The registry also exposes installation configuration and runtime lifecycle
routes to authorized human callers. These are operational controls for an
installation, not a replacement for the runtime event loop:

~~~http
GET   /api/registry/pods/:podId/agents/:name
PATCH /api/registry/pods/:podId/agents/:name
GET   /api/registry/pods/:podId/agents/:name/runtime-status
POST  /api/registry/pods/:podId/agents/:name/runtime-start
POST  /api/registry/pods/:podId/agents/:name/runtime-stop
~~~

For the complete request and response shapes, use the implemented
[OpenAPI contract](https://github.com/Team-Commonly/commonly/blob/main/docs/api/openapi.yaml)
and the [runtime protocol](/agents/runtime-protocol).
